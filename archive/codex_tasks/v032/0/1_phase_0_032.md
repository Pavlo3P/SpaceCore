# Task: Stabilize minimal-install test and CI behavior after 0.3.1

## Goal

Make a clean SpaceCore checkout pass test collection and the NumPy-only test suite under the documented minimal development install, without requiring optional JAX or Torch dependencies.

The minimal install is:

```bash
pip install -e ".[dev]"
```

This task should not add JAX or Torch to the minimal dependency set.

## Required fixes

### 1. Guard JAX usage in functional tests

Inspect:

```text
tests/functional/test_metric_gradient.py
```

Fix any module-level construction of `JaxOps` or JAX-backed contexts. Optional backend objects must be constructed only inside guarded tests or fixtures.

Expected behavior:

```bash
pip install -e ".[dev]"
pytest --co -q
```

must succeed without JAX installed.

JAX-specific cases should skip cleanly, not fail during import or collection.

### 2. Audit optional backend references

Search the test suite for unguarded references to optional backends:

* `JaxOps`
* `TorchOps`
* `CuPyOps`
* `jax`
* `torch`
* `cupy`

Any test requiring an optional backend must use the existing backend-availability helpers, or add such helpers if missing.

Done condition:

```bash
pytest tests/ -q
```

in a NumPy-only environment gives only passes/skips, with zero collection errors.

### 3. Fix Torch namespace test guard

Find the test named:

```text
test_torch_ops_uses_aac_namespace_when_available
```

Add the same kind of skip guard used by its sibling Torch tests, for example:

```python
pytest.mark.skipif(not has_torch(), reason="torch is not installed")
```

The test must skip, not fail, when Torch is absent.

### 4. Backfill 0.3.1 changelog metadata

Update `CHANGELOG.md`:

* add the `2026-06-10` release date to `[0.3.1]`;
* add the `[0.3.1]` comparison/release link in the link block;
* keep formatting consistent with existing `0.3.0` and `0.2.0` entries.

### 5. Resolve docstring-check strictness mismatch

Inspect CI and release-candidate validation around:

* `scripts/docstring_audit.py`
* `ruff --select D`
* `scripts/verify_release_candidate.sh`

If CI currently tolerates docstring failures with `|| true`, either:

1. remove the tolerance and make CI strict; or
2. document intentionally that CI is tolerant but the release-candidate script is strict.

There must be no silent divergence between CI and release validation.

### 6. Add minimal-install CI job

Add one CI matrix entry that installs only:

```bash
pip install -e ".[dev]"
```

and runs:

```bash
pytest --co -q
pytest tests/ -q
```

This job locks in that optional JAX/Torch/CuPy dependencies are not required for collection or the NumPy-backed test suite.

## Acceptance criteria

The task is complete when:

```bash
pip install -e ".[dev]"
pytest --co -q
pytest tests/ -q
```

passes in an environment without JAX, Torch, or CuPy installed;

optional-backend tests skip cleanly;

`CHANGELOG.md` has complete 0.3.1 date/link metadata;

CI includes a minimal-install job;

docstring-check strictness is either enforced consistently or explicitly documented.
